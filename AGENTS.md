# sotto — local, offline push-to-talk dictation: hold a key, speak, release; text lands at the cursor. macOS: PyObjC + mlx-whisper on Metal. Windows source alpha: `sotto_win.py` — pynput trigger hook (right-ctrl default), default-input capture (PortAudio's MME host API, not WASAPI), pinned faster-whisper (CUDA float16, CPU int8 fallback), paste-or-type insertion, pystray tray + Tk dialogs (`--tray`).

Two lanes share this code. The **alpha** is what users install and run. The **sealed adaptive lane** is the maintainer's own LaunchAgent deployment with the learning system; users never run it. Rules under "Shared code rules" apply to both.

## Alpha (what users run)

### Run & test
All Mac commands run from the repo root with the alpha venv `venv-alpha` (Apple Silicon).

- Source alpha: native Python 3.12, macOS 14+ (dependency floor; only 27.2 tested). `python3.12 -m venv venv-alpha && venv-alpha/bin/python -m pip install -r requirements-alpha.txt`; keep the sealed runtime dependency policy separate.
- Install/update/remove: `scripts/install-mac.sh` (Mac) and `scripts\install-windows.ps1` (Windows). These are the alpha's only install paths; `scripts/rollout.sh` is the sealed lane's deploy and never applies to the alpha.
- App: `scripts/install-mac.sh [--update|--uninstall]` builds `Sotto.app` in `/Applications` when writable, else `~/Applications`, removing our other copy (compiled launcher from `scripts/install_app.py`, ad-hoc signed, `SOTTO_LAUNCHER=app`); login item `org.sotto.alpha` via `login_item.py` (never the sealed label).
- Data folders: the installers keep alpha state in `sotto-alpha` by setting `SOTTO_DATA_DIR` — Mac `~/Library/Application Support/sotto-alpha` (`install-mac.sh` and the `Sotto.app` launcher), Windows `%LOCALAPPDATA%\sotto-alpha` (`install-windows.ps1` via `win_launch.py`); the model cache follows as `<data>/huggingface`. A bare `sotto.py run` without `SOTTO_DATA_DIR` uses `sotto_paths`' default (`~/Library/Application Support/sotto`, `%APPDATA%\sotto`), so it sees different history and settings than the app.
- Source launch: export `SOTTO_DATA_DIR` and `SOTTO_HF_HOME` to dedicated alpha folders; see README. To run against the app's own data: `SOTTO_DATA_DIR="$HOME/Library/Application Support/sotto-alpha" venv-alpha/bin/python sotto.py run` (models then come from `sotto-alpha/huggingface`). Never use personal state for tests.
- Permissions check: `venv-alpha/bin/python sotto.py doctor`  (Accessibility + mic; same `SOTTO_DATA_DIR` as the run)
- Run: `venv-alpha/bin/python sotto.py run` (trigger/hotkey come from Settings, default right Option; `--trigger`/`--hotkey` override one run). `sotto.py setup [--profile parakeet]` pre-downloads pinned models + Silero VAD; `sotto.py dictionary` lists rules.
- Full test suite: `venv-alpha/bin/python -m unittest discover -s tests`  (unittest; slow — loads heavy modules). `tests/test_00_hermetic.py` sorts first and points `SOTTO_DATA_DIR`/`SOTTO_HF_HOME` at a temp folder before anything imports `sotto_paths`, so a run never touches real user data; a single-module run skips it, so use `scripts/test_alpha.py -p <file>` for one module.
- Isolated alpha verification: `venv-alpha/bin/python scripts/test_alpha.py` (temporary data/cache; optional public calibration inputs require explicit `SOTTO_CALIBRATION_FIXTURES`).
- One module: `venv-alpha/bin/python scripts/test_alpha.py -p test_speech_config.py` (or `venv-alpha/bin/python -m unittest tests.test_00_hermetic tests.test_speech_config`; do NOT run `venv-alpha/bin/python tests/<file>.py` directly — cwd isn't on `sys.path`, imports fail)
- Alpha tests do not install workers or enable adaptive routing. Run them from a checkout without world-writable or symlinked ancestors (not /tmp); `scripts/test_alpha.py` refuses otherwise because the comparator-spool guards reject such paths.
- Windows PC suite: `venv\Scripts\python scripts\test_alpha.py` (temp state + offline flags; plain `unittest discover -s tests` is hermetic too, via `tests/test_00_hermetic.py` — do NOT add `-t`; a global site-packages `tests` package shadows the repo's `tests/` dir). macOS-only tests self-skip on win32 (each skip carries a reason string).
- Windows PC run: `venv\Scripts\python sotto_win.py` (console; `--tray` for the tray app; `--device cpu|cuda` or `SOTTO_DEVICE`; `doctor`, `history`, `history-delete --id`, `history-clear --yes`). Testers: `scripts\install-windows.ps1` (venv, pinned CPU/CUDA set — a re-run keeps the recorded one, Start Menu shortcut via `win_launch.py` + pythonw; refuses while Sotto runs from the venv or when `Sotto.lnk` starts another existing copy; `-WhatIf`, `-Uninstall`) and `docs/windows-alpha.md` (Python 3.13 x64; `requirements-alpha-windows.txt` CPU set + lock, `requirements-alpha-windows-cuda.txt` adds cuBLAS + its lock). `scripts\sotto-win.bat` is the dev shortcut.
- Gesture acceptance (8 scenarios): `venv-alpha/bin/python tests/gesture_check.py`  (wall-clock timed — run locally, flaky on CI runners)
- Syntax-only check: `venv-alpha/bin/python -m compileall -q *.py tests`
- Lint: `venv-alpha/bin/python -m pip install ruff==0.16.10 && venv-alpha/bin/python -m ruff check` (rules in `pyproject.toml`: E/F/W/B at 120 columns; the sealed lane's modules and tests are excluded for now; CI job `lint` in `tests.yml`). Fix findings or add a narrowly-justified per-file ignore; don't reformat whole files.

### Dependencies
- The alpha's dependency truth is `requirements-alpha*.txt` + `constraints-alpha*.txt`: `constraints-alpha.txt` (Mac, Python 3.12), `constraints-alpha-windows.txt` (Windows CPU, Python 3.13) and `constraints-alpha-windows-cuda.txt` (adds cuBLAS). Every installer and manual step bootstraps one exact pip (`pip==`). `tests/test_dependency_pins.py` fails when a package pinned in both the Mac and a Windows lock differs, unless `PLATFORM_DIFFERENCES` gives the reason (today: `huggingface-hub`, capped below 2.0 by Windows' tokenizers).
- The sealed lane's dependency truth is separate (`requirements.txt` + `runtime_dependency_policy.json`, below). Never edit one set to fix the other.

### Alpha-only rules
- `install-mac.sh --update` fetches, records the installed packages, installs the new version's (restoring the old set if that fails — pip has no rollback), and only then fast-forwards the source; `scripts/update-windows.ps1` does the same on Windows with the recorded CPU/CUDA set, then reruns the installer, writes `update-status.txt` (the tray reports it) and starts this copy again (the shortcut only if it points here). `updates._git` passes `CREATE_NO_WINDOW` on win32. After an update the app closes `CaptureGate` (no new recordings), waits until nothing is recording, transcribing or waiting to paste (`dictation_in_flight`, at most `UPDATE_DRAIN_DEADLINE_S`), then restarts; a failed restart reopens the gate. `install_app.build` never replaces a `Sotto.app` it did not build.
- Sotto.app permissions (2026-09-30): `AXIsProcessTrusted()` asks tccd once per process and then repeats that answer, so the app-mode dialog polls a fresh child (`accessibility_granted_now`) and relaunches after the grant. Sotto.app never `execv`s in place: same-pid exec leaves the new menu bar icon blank and unclickable (2026-10-01), so restarts go through `relaunch_app_after_exit` (detached helper waits for the launcher, then kickstarts the login item or `open -n`s the app). The bundle is ad-hoc signed, so TCC pins the grant to that exact build ("Failed to match existing code requirement" in tccd logs); `build` keeps an identical bundle untouched — don't churn the launcher. Alerts come from Python, so `ui.use_app_icon` sets Sotto's icon.
- Windows ASR: `win_asr.resolve_model_dir` runs once at startup — a complete cached snapshot of the pinned commit loads with no network call, a missing one downloads only when no offline flag is set, and `WhisperModel` only ever gets that local directory. The first (warmup) transcription is the device probe: CTranslate2 loads cuBLAS lazily, so a CUDA failure surfaces there and falls back to CPU int8 unless `--device cuda` was forced. The idle rewarm runs only on CUDA (a CPU decode would queue ahead of the dictation). `win_capture` binds each opened stream to its capture generation so a slow open can never leave the mic running, and stops/closes a finished stream on its own thread (the next open waits for it); insertions run on one FIFO thread and wait while any modifier is held, each at most `INSERT_WAIT_S` from when its text was ready; nothing file- or icon-related runs on the keyboard-hook thread (`_ConsoleLog` only queues lines; its writer thread does the I/O). A model exception keeps the capture as a `live_suspect` History row `[transcription failed]` (Retry recovers it) and notifies the tray. Restart/Speed wait for the dictation in flight up to `RESTART_DRAIN_CAP_S` (5 min; past it a wedged CUDA/CT2 call is abandoned and logged). Quit (off the tray thread) ends a recording in progress like the tray's Finish (copied, orphans too) and waits up to `QUIT_DRAIN_S` (10 s, the Mac's) until nothing is recording, transcribing, queued for insertion or waiting for the app to read a paste (`win_inject.paste_settling`); insertion after shutdown stays refused. Restart, Update and Quit close one `sotto.CaptureGate` that `on_start` begins captures under; Update closes it before its busy check and reopens it when refused or when the updater cannot start, then quits through the Quit drain. The resync poller revives the hook only under the lock the teardown stops it with, after checking shutdown, so it never revives the hook during teardown. A restart passes an absolute script path. Automatic = detect then argmax within the Settings languages (`speech_config.automatic_languages`), decoded with that language fixed, reusing the detection's encoder pass for clips up to 30 s (`LanguageRestricted.last_language` -> `preprocessing["detected_language"]`). Dictionary via `sotto.apply_personal_dictionary` only on delivered text (live and retry); `latency.release_to_text_seconds` and the shared `progress` module match the Mac. Paste = delayed rendering from a clipboard-owner window (compare-and-restore on that thread after the foreground app reads it, retried if busy; owner-marked private content is typed instead; a tray-finished dictation is copied, not inserted); own injected keys carry `win_inject.INJECTED_TAG` so the hook ignores them. One dictation app per Windows session (named mutex; tests set `SOTTO_INSTANCE_KEY`). Real-clipboard tests run in a private window station.
- An unreadable `history.jsonl` (damaged row, duplicate id, newer schema) raises `history.HistoryUnreadable`. Only the dictation apps (`run()` when not adaptive, `sotto_win.run()`) open History with `tolerate_unreadable=True`: the file and its WAVs are left untouched (no sweep, no rewrite, no move), `sotto.history_coordinator` returns `UnsavedHistory` (dictation delivered, nothing saved; every History action raises), and the user is told once. Never "recover" by deleting or moving the index: a launch without one sweeps every WAV as an orphan. Workers, CLIs and the adaptive lane stay fatal. `progress.record` starts from zero only when `stats.json` is missing; any other read error skips that update (F38).
- History Delete/Clear on Windows go through the same `sotto.nonadaptive_delete`/`nonadaptive_clear` as the Mac menu. `adaptive_learning` locks via `storage_lock.lock_exclusive` (fcntl on macOS, msvcrt on Windows); `ComparatorSpool.scrub` without dir_fd authority (Windows) is complete only when the spool is absent.

## Maintainer / sealed adaptive lane
The maintainer's production install: venv `venv` with `requirements.txt`, pinned and verified against `runtime_dependency_policy.json` by `sealed_release.py`; the sealed LaunchAgent from `launchd/`; data in `sotto_paths`' default folder. `scripts/rollout.sh` runs its preflight and `compileall` with `venv/bin/python`.

- Deploy ONLY via `scripts/rollout.sh` (stage → activate → preflight under the new release → back up/install/reload the sealed LaunchAgent → verify, with automatic LKG + plist rollback and re-preflight on boot failure). This rule is for the sealed maintainer deployment; the alpha installs via `scripts/install-mac.sh` / `scripts\install-windows.ps1`. `kickstart` alone does not reload changed ProgramArguments. Receipts are sealed to `runtime_source_digest()`, so any source change invalidates them; deploying by hand and skipping the preflight crash-loops the app at warmup ("adaptive baseline preflight receipt is invalid" — bit 4 rollouts before the script).
- `launchd_templates.py` renders home/FFmpeg placeholders during rollout; never install raw templates.
- Do not install the silver worker before public Calibration V2 and strict sealed readiness pass. Afterward it may collect shadow-only personal evidence; candidate routing remains impossible until personal evaluation authorizes at least 500 captures over at least 7 days.
- The learning system is gate-heavy on purpose (receipts, digests, revocation tombstones, one-shot promotion). Preserve those invariants; don't loosen them for convenience.
- Sealed runtime markers must survive harmless cross-boot APFS `st_dev` renumbering. Persist paths, inode/size/timestamps, exact tree membership, and SHA-256 bytes; use `st_dev` only for within-process race/alias checks, never as durable identity.
- Adaptive/"silver" learning lane (headless `adaptive_worker.py`): `adaptive_learning.py`, `adaptive_runtime.py`, `silver_store.py`, `learning.py`, `history.py`, `teacher_backends.py`, `teacher_provision.py`, `calibration_worker.py`, `deployment_controller.py`, `sealed_release*.py`.
- `teachers/` — Qwen3-ASR + Granite teacher adapters with isolated requirements; `launchd/` — plist templates; `docs/` — learning design notes.

## Shared code rules (both lanes)

### Structure
- `sotto.py` — main entry + CLI (`run`/`doctor`/`learning-*`): GestureEngine, RecordingSession, cursor injection, LearningCoordinator/HistoryStore/LearningStore. `transcription.py` — `TranscriptionWorker`, the single-flight job loop (`live`, `retry`, `warmup`, Nemotron `stream-*`) that `run()` builds with its collaborators and starts on the worker thread; it calls `pipeline.screen()` for live and Retry. `tests/test_transcription_worker.py` is its golden master: drive it with fakes, never the real model.
- `speech_backends.py`, `speech_config.py`, `vad.py`, `ui.py` — mlx Whisper/Parakeet backends & profiles (pins in `MODEL_REVISIONS`, 100 `WHISPER_LANGUAGES`, `automatic_languages`), voice-activity detection (pinned Silero v6.2, verified on load), and the AppKit menu-bar + ember-orb overlay.
- Engines in `sotto.py`: `LocalWhisper` (one encoder pass for Automatic ≤30 s, experimental Fast = trimmed encoder, `choose_language` never translates clearly-other speech, unsure decodes and exhausted token budgets fall back to the full pipeline) and `LocalParakeet` (Parakeet TDT v3 on MLX, 25 European languages, array input, 120 s chunks); both resolve pinned snapshots via `resolve_pinned_snapshot` (cache-first, local path only).
- `pipeline.py` — owns what happens to a transcript before delivery: `screen()` = no-speech verdict → hallucination guard with repetition-loop salvage → personal dictionary → English voice cleanup. macOS live and Retry both call `screen()`; Windows still calls the pieces through `sotto`'s re-exports. Change transcript screening here, never in a platform entry point.
- Shared pure modules (macOS + Windows): `dictionary.py` (heard => write rules, correction suggestions), `settings.py` (settings.json), `progress.py` (History trends, no text). macOS UI: `settings_window.py` (PyObjC, `@objc.python_method` helpers).
- `nemotron_backend.py`, `streaming_audio.py` — optional, manually selected English streaming ASR using pinned NeMo-Speech.cpp Metal libraries; provision with `scripts/setup_nemotron.py` from the lane's venv (`venv-alpha` or `venv`) and under the same `SOTTO_DATA_DIR` as the app (Apple Silicon only). Pins live in `config/nemotron-runtime.json`; runtime only loads verified local files.
- `sotto_win.py` + `win_asr.py` / `win_capture.py` / `win_hotkey.py` / `win_inject.py` / `win_ui.py` (tray, Settings, Correct) / `win_startup.py` (HKCU Run login entry) / `win_launch.py` (pythonw entry) — Windows app (no overlay, no adaptive lane, no Nemotron). CT2 model ids live in `win_asr.PROFILES` (+ `FAST_REPO` for Settings speed "fast"), exact commits in `win_asr.REVISIONS`, per-repo file sets in `win_asr.REPO_FILES`; `speech_config.MODEL_PROFILES` still names the MLX repos for the Mac. Shared `dictionary.py`/`settings.py` are Mac-owned APIs.
- `tests/` — unittest suite.

### Conventions & danger zones
- macOS runtime: Quartz/AppKit import at module scope (guarded in `sotto.py` so the pure logic imports on Windows; the `win_*` modules raise `ImportError` off win32, and their tests skip with a reason). CI runs the unit suite on a macOS runner (`.github/workflows/tests.yml`, Homebrew Python 3.12); the older `ci.yml` stays tombstoned because it needs `actions/setup-python` — see `.github/workflows-disabled/README.md`. Style: PEP 8, f-strings, `pathlib`.
- `sotto_paths.py` is the only place that decides storage: macOS `~/Library/Application Support/sotto` (+ `Sotto/huggingface`), Windows `%APPDATA%\sotto` (+ `huggingface`); `SOTTO_DATA_DIR`/`SOTTO_HF_HOME` override (blank = unset). Never add per-module platform path logic. `sotto_paths.py` centralizes alpha data/cache overrides without moving legacy data (the alpha's `sotto-alpha` folders come from the installers, above).
- Fully local/offline by design — no cloud, no telemetry, no speech upload. Check for Updates (`updates.py`) is the only network call outside model setup, and only on the user's click; offline flags disable it. Text delivery uses `deliver_call`, never the UI-only `ui_call`, so `--no-overlay` still pastes. Inference must never resolve HuggingFace Hub ids. Startup resolves the exact commit pinned in `speech_config.MODEL_REVISIONS` cache-first (no network when that snapshot is cached), downloads it only on a first non-offline run, and passes inference a local path; offline flags forbid downloads.
- The production LaunchAgent keeps only the selected ASR model resident. With `--idle-release 0`, key-down starts the microphone engine/input tap and key-up stops/removes them; idle Sotto must not hold the microphone or retain idle audio. Whisper remains the default with sealed `config/sotto-glossary.txt`; optional Nemotron is a manual English-only engine, never an adaptive candidate or promotion.
- The Speech engine submenu persists the choice and restarts only its own foreground process or supervising sealed LaunchAgent while idle. Nemotron (`--profile nemotron-en`) streams canonical PCM on the single transcription worker, retains exact inference bytes for History/retry, and pastes finalized text only. It disables non-English/automatic language and Whisper glossary prompts; returning to Whisper restores the saved language choice. Never feed VAD-gated chunks or run MLX/native inference on the audio tap. Native load failure restores Whisper; native streaming failure retries the full canonical capture once.
- Automatic language defaults to English only; users add their languages in Settings and each capture is detected among them. No language besides English is a default or special-cased. The menu-bar Language submenu persistently selects Automatic or one chosen language by changing only the decode hint; it must not load a second model or change the push-to-talk microphone lifecycle.
- After four idle minutes, the next baseline press schedules one single-flight model rewarm on the serialized transcription worker while capture is active; never move it to a concurrent MLX thread.
- The ember overlay follows the display containing the pointer on every visible state and verifies WindowServer visibility after raising; preserve its one-shot panel rebuild and local diagnostic logging.
- The VAD is advisory only (trim + no-speech verdict AFTER transcription via `reads_as_no_speech`). Never reintroduce an input-side gate that blocks captures from reaching the ASR: Silero scores real whispered dictation at 0% speech, and energy thresholds break on quiet whispering (2026-08-13/14 incidents). Exact-zero PCM is a dead mic route, not a quiet room (`asr_skip_reason`); it must not reach Whisper (2026-09-20: 41s of 24 kHz zeros → `"ощ"` x223).
- Bit-exact zero PCM means THIS PROCESS's capture path is wedged, not that the room is quiet. 2026-09-20: AirPods reconnected under a new CoreAudio device id and every capture came back all-zero — including ones pinned to the built-in mic — while ffmpeg read those same AirPods at peak 18609 and a fresh process running `CaptureService` captured at peak 0.059. Stop/start does NOT clear it: the `AVAudioEngine` object is reused for the process lifetime and carries the wedged HAL input unit across rebuilds. `_repair_dead_route` drops `_engine_obj` first and relaunches via launchd second (guarded by `SILENCE_RESTART_AFTER_S` so it cannot loop); the counter rearms only on real audio in `_tap`, never on engine start. Bluetooth warm-up emits ~410 ms of leading zeros, so the key-up rung needs >=1s of zeros before it fires.
- `looks_hallucinated` is whole-transcript, so a whisper repetition loop that starts partway through used to cost the user the real dictation in front of it (2026-08-15: 403 good chars lost to `"difference"` x223). `salvage_repetition_loop` cuts at the loop and pastes the clean prefix, but only when that prefix passes the same guard on its own — keep it conservative; wall-to-wall garbage must still be quarantined, never pasted.
- A failed live transcription (Whisper or Nemotron, non-adaptive) must never lose the recording: `TranscriptionWorker._keep_failed_live_capture` appends a `live_suspect` row reading `[transcription failed]` with the raw audio and the error in its receipt, logs the error type, and shows one alert so the user can Retry it (F4). A failed History append must never lose the text: for non-adaptive dictation the delivery a saved row would have scheduled still runs (held text stays off the cursor) and one "History could not be saved" alert is shown (F16a). The adaptive lane keeps its own fallback and append-before-deliver — its row is part of its receipts. Both stay silent once shutdown is requested.
- macOS disables session event taps silently (no callback notification) — 2026-09-15: process healthy, tap `enabled=False`, 3 hours of dead hotkey. `resync_poller` checks `CGEventTapIsEnabled` every second and calls `revive_tap` DIRECTLY on the poller thread — never via `AppHelper.callAfter` (the 2026-09-15 version did that and never fired; 2026-09-16 tap dead again). The menu bar has "Restart sotto" (bounded, drained exec for a foreground run; off-main-thread `launchctl kickstart -k` only when that job owns this PID; a process that looks sealed/launchd-started but cannot be confirmed refuses — never exec outside the bootstrap) because a clean Quit is a SuccessfulExit that KeepAlive does not relaunch. Diagnose with `Quartz.CGGetEventTapList` (look for the app pid with mask `0x1c00`).
- Quit, the menu Restart and the first SIGINT/SIGTERM stop the same way (`Lifecycle` in sotto.py): close the capture gate, end the recording as a normal finish, wait for `dictation_in_flight` (a model rewarm does not count) up to `QUIT_DRAIN_S`, or `SIGTERM_DRAIN_S` because launchd SIGKILLs the job 5 s after SIGTERM; a second signal stops at once. The signal handler only sets an event. While the gate is closed (quitting, restarting, updating, switching engines) a key press, the menu start and Retry are refused and the gesture is left idle; the engine switch closes the gate before its last in-flight check.
- The teardown (`stop_runtime_on_main`) runs a pending clipboard restore before the process ends (still changeCount-guarded), keeps every live capture still untranscribed as a `live_suspect` History row with its audio for Retry (queued, refused by the queue, the one the model is still on, or one the worker abandoned; `TranscriptionWorker` settles each capture id once, so none is saved twice), and a foreground restart whose exec fails exits `RESTART_FAILED_EXIT` (75), never 0, so KeepAlive starts Sotto again.
- Live words (`StreamingCapture.live_text`, the pill) are display only: never paste, log or store an interim. The pill shows them through `sotto.live_preview` (dictionary rules only) so its spellings match the pasted text. Voice commands and filler cleanup (`voice_commands.py`) run after the dictionary, English only ("um" is a Portuguese word); "scratch that" undoes only Sotto's own insert: `inject()` must have reported a real insert (a secure-input decline arms nothing), the same frontmost pid as at insert time, no real user key-down since (the tap counts them, excluding Sotto's tagged events), and inside `SCRATCH_WINDOW_S`; otherwise do nothing and log why. `stats.json` holds counts, never text.
- Text delivery (`DeliveryQueue` in sotto.py) is one FIFO on the main thread: results paste in capture order, and nothing is posted while the trigger or any modifier is physically held (wait while a recording is active; after `DELIVERY_WAIT_MAX_S` with no recording, drop with one note — the text is in History). `deliver_call` counts each paste/undo in `PendingDeliveries` and the queue's `on_done` finishes exactly one entry per item it delivers, drops or clears at shutdown, so Quit (`QUIT_DRAIN_S`) and the update restart wait for the paste and never for a leaked count. Every key event Sotto posts carries `SOTTO_EVENT_TAG` (`post_own_event`), and the tap callback ignores tagged events. The clipboard restore after ⌘V waits `RESTORE_DELAY_S` and carries the user's original forward across overlapping pastes; a user copy in the window still wins (changeCount).
- GitHub Actions must stay SHA-pinned — `tests/test_workflow_action_pinning.py` enforces this.
- `venv/`, `venv-alpha/`, `__pycache__/`, `.panel/`, `.handoff/` are gitignored — never commit them.

## Agent rules (all harnesses)
- Determinism boundary: anything that must be EXACT lives in code; the model only orchestrates and judges.
- Keep this file current: when you change how this repo is run, tested, or structured, update AGENTS.md in the same commit. Keep it under ~150 lines.
